# TGCV — Rust ΔT_acc → ΔReach / ΔTrajectory Structural Link Gate v0.1

**Status:** RECONSTRUCTED / WORKING

## 1. Purpose

This gate specifies the next outcome-blind structural test after successful reconstruction of paired Rust `T_acc` and `ΔT_acc`.

The question is whether the already reconstructed accessible-transformation space can be linked to distinct reachable-future and trajectory structures without collapsing the three analytical objects into one another.

No outcome, value, predictive model, or causal claim is introduced by this gate.

## 2. Locked starting point

- `Core_ontological = S`
- `T_acc,t = {(e_o, τ_id) | P_τ(e_o,t)=1}`
- `ΔT_acc = T_acc,t1 ≄ T_acc,t0`
- `Reach` and `Trajectory` remain distinct downstream analytical objects.
- `I` remains explanatory, not a Core primitive.
- SLR-1 remains closed.
- TR-130–TR-140 remain closed.
- R* v0.2 remains frozen.
- EXT-1.1 predictive outcome/model remains excluded.

## 3. Definitions

### 3.1 Reach

For a focal state `S_t` and accessible transformation relation `T_acc,t`, `Reach_t` is the set of states/configurations/futures that can be reached through admissible finite sequences of accessible transformations under fixed transition semantics.

`Reach_t = Reach(S_t,T_acc,t,C_t,L)`

The construction must not use observed future success or outcome to define reachability.

### 3.2 Trajectory

`Trajectory_t` is the set or structure of admissible temporal paths generated by successive accessible transformations under the frozen transition semantics.

Trajectory is not merely the endpoint set `Reach`.

## 4. Required distinctions

The implementation must preserve:

`T_acc ≠ Reach ≠ Trajectory`

Specifically:

- `T_acc` describes currently accessible transformation alternatives;
- `Reach` describes futures/states obtainable through admissible transformation sequences;
- `Trajectory` describes temporal/path structure among successive transformations and states.

A cardinality correlation between these objects is insufficient to establish analytical identity or dependency.

## 5. Structural link to test

The intended analytical relation is:

`T_acc,t → Reach_t → Trajectory_t`

and, conditionally:

`ΔT_acc → ΔReach → ΔTrajectory`

The arrows denote analytical constraint/dependency under fixed transition semantics. They do **not** assert universal causality.

## 6. Non-degenerate constructions

The implementation must be capable of representing at least the following cases, whether observed in the Rust data or explicitly marked as not reconstructable:

### RT-T1 — ΔT_acc without ΔReach

A transformation becomes accessible but is redundant with an already reachable alternative.

### RT-T2 — ΔT_acc with ΔReach

A newly accessible transformation enables a future that was not reachable under the prior accessible set.

### RT-T3 — ΔT_acc with trajectory reconfiguration

The reachable endpoint set may remain unchanged while the structure or multiplicity/order of admissible paths changes.

### RT-T4 — same realized path, different counterfactual trajectory space

Observed execution alone must not define the trajectory space.

### RT-T5 — Reach change without identical T_acc change

A reachability change may also arise from changed state or contextual constraints. This prevents the false identity `ΔReach ≡ ΔT_acc`.

## 7. Rust operationalization boundary

The Rust instantiation must use only structural information available under the frozen paired comparison.

The candidate transformation remains:

`τ = dependency-transition(origin_package_version,target_package,target_version)`

The accessibility relation is inherited from the frozen present-state predicate and R* v0.2.

Any proposed transition-sequence semantics must be specified independently of outcome and must not be inferred from which dependencies were later selected or successfully used.

If the available Rust dataset cannot reconstruct executed dependency transitions or sufficient transition semantics for genuine multi-step reachability, the audit must report **NOT RECONSTRUCTABLE** rather than substitute an outcome-derived proxy.

## 8. Required structural representation

At minimum, the audit must be able to represent:

1. focal state identity;
2. accessible transformation memberships at t0 and t1;
3. transformation application/transition semantics, if observable;
4. successor-state identity, if reconstructable;
5. admissible transformation sequences, if reconstructable;
6. `Reach_t0` and `Reach_t1`, if reconstructable;
7. `Trajectory_t0` and `Trajectory_t1`, if reconstructable;
8. differences `ΔReach` and `ΔTrajectory`.

No outcome variable may be used to fill missing structural semantics.

## 9. Reconstruction levels

Use the existing operational levels:

- **R0 Direct:** explicitly observed structural semantics;
- **R1 Reconstructed:** deterministically reconstructed from observable records;
- **R2 Partial:** only part of the required structure is reconstructable;
- **R3 Proxy:** indirect substitute; insufficient for a primary structural identity claim without separate proxy validation.

A result based only on R3 must not be presented as a direct validation of the TGCV architecture.

## 10. Primary tests

### Link test L1

Can `Reach_t` be deterministically reconstructed from `S_t`, `T_acc,t` and frozen transition semantics without outcome leakage?

### Link test L2

Can `ΔReach` be reconstructed from paired `Reach_t0` and `Reach_t1`?

### Link test L3

Can `Trajectory_t` be distinguished from `Reach_t`?

### Link test L4

Can `ΔTrajectory` be reconstructed independently of realized outcome?

### Link test L5

Can at least one non-degenerate structural case distinguish `ΔT_acc` from `ΔReach`?

### Link test L6

Can at least one non-degenerate structural case distinguish `ΔReach` from `ΔTrajectory`?

## 11. Falsifiers

**F-RL1:** `Reach` necessarily reconstructs `T_acc` with no information loss under the correct Rust semantics.

**F-RL2:** `Trajectory` necessarily reconstructs `T_acc` or `ΔT_acc`, making the distinction analytically redundant.

**F-RL3:** no transition semantics independent of outcome can be reconstructed.

**F-RL4:** every observed `ΔT_acc` maps identically to `ΔReach`, with no possible distinction between redundant and reach-changing accessibility changes.

**F-RL5:** trajectory structure cannot be distinguished from endpoint reachability.

**F-RL6:** accessibility must be defined from future execution or outcome.

**F-RL7:** the only available implementation is an outcome-derived proxy.

**F-RL8:** cross-domain distinction fails when the Rust construction is mapped back to the locked TGCV architecture.

## 13. Decision

**PASS — STRUCTURAL LINK TEST SPECIFIED; RUST REACHABILITY / TRAJECTORY RECONSTRUCTABILITY REMAINS OPEN.**

A failure of Rust reconstructability would be a bounded domain limitation, not an automatic rejection of the TGCV architecture.
