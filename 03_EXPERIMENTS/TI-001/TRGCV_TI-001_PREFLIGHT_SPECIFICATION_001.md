# TGCV — TI-001 Preflight Specification
## Pre-Execution Package Specification 001

**Date:** 2026-09-24  
**Status:** PRE-FLIGHT SPECIFICATION — SCIENTIFIC EXECUTION NOT AUTHORIZED  
**Basis:** TI-001 Design 001, TI-001 Design Audit 001, TSDA Formal Analytical Artefact 001.

## 1. Purpose

This specification converts the TI-001 conceptual design into a machine-checkable preflight boundary. It does not execute the experiment and does not authorise scientific execution.

The preflight must establish that the treatment changes access to information about transformation-space structure/evolution while holding the currently executable transformation set and ordinary task information constant.

## 2. Experimental unit

Each independent instance is a finite-state decision environment containing a current state S_t, a common current accessible transformation set T_acc,t, candidate transformations, and successor states whose accessible transformation spaces differ according to the selected transformation.

The unit of analysis is a matched control/treatment pair generated from the same frozen instance.

## 3. Minimum instance structure

Every instance must contain:

- at least one current state S_t;
- at least two currently executable transformations;
- identical T_acc,t in control and treatment;
- at least two candidate transformations with distinct future transformation-space consequences;
- a deterministic or frozen stochastic transition rule;
- a successor state for each realised transformation;
- reconstructable T_acc,t+1 for every successor;
- a future reconfiguration property not uniquely inferable from current state/action information alone;
- no payoff label or preferred-action label in the treatment information.

## 4. Control and treatment

### Control

The system receives only information necessary to identify and execute currently available transformations and the ordinary task specification.

### Treatment

The system receives the same control information plus a structured representation of future transformation-space structure/evolution.

The additional representation may encode TSDA-compatible descriptors or relations such as successor accessibility, identity turnover, persistence, or reconfiguration class.

The treatment representation must not encode:

- an action recommendation;
- a reward or utility ranking;
- a preferred successor label;
- a direct outcome prediction;
- a transformation identity as the uniquely selected answer.

## 5. Leakage gate

The preflight must reject an instance if treatment information permits an independent checker to identify a unique preferred transformation without performing the intended transformation-space reasoning.

Required checks:

1. Current T_acc is identical across conditions.
2. Current action identities are identical across conditions.
3. Control information does not reveal the treatment-only future descriptor.
4. Treatment information does not contain an explicit action ranking.
5. Treatment information does not contain reward, utility or outcome ranking.
6. At least two transformations remain admissible after receiving treatment information.
7. No single treatment token or field is a direct alias for the selected transformation.
8. The future transformation-space distinction is generated by the transition structure, not inserted as a preferred-action label.

## 6. Null/control design

At least one null condition should be included in the preflight package.

The null should provide information with comparable structural complexity but without predictive information about future transformation-space reconfiguration.

The null must be checked for:

- equal current action-set information;
- comparable information volume/format where practicable;
- absence of future-space signal;
- absence of action recommendation;
- absence of reward/outcome information.

The null is a control for generic information exposure and formatting effects.

## 7. Anticipation condition

For an anticipation-capable instance, the future transformation-space property must not be uniquely reconstructable from S_t and T_acc,t alone.

The preflight checker must independently reconstruct all information available under control and demonstrate that the treatment-only future-space descriptor is not derivable from that information.

The decision must occur before the successor state and its realised accessibility are revealed.

## 8. Randomisation

Each matched instance must receive a frozen condition assignment generated by a declared randomisation procedure.

The randomisation seed, assignment, instance identifier and generated environment must be persisted.

Condition labels must not be inferable from the environment's action identities or state identifiers.

## 9. Primary estimand

The primary estimand is the matched-condition difference in transformation handling.

Primary observable:

`Choice(Control, instance) != Choice(Treatment, instance)`

with aggregation specified as a pre-registered proportion or equivalent paired statistic across independent instances.

No intelligence score is permitted.

Secondary observables may include consistency with future-space reconfiguration and cross-instance replication.

## 10. Falsification gates

The preflight must mark the instance invalid if:

- current T_acc differs between conditions;
- current task information differs materially outside the treatment manipulation;
- treatment directly identifies a preferred action;
- treatment reveals reward or outcome ranking;
- future-space information is already derivable from control information;
- the decision occurs after future information becomes observable;
- only one executable transformation exists;
- the instance contains an unmarked domain-specific shortcut;
- the instance is not independently reconstructable.

An invalid instance is excluded before scientific interpretation.

## 11. Frozen data schema

Every generated record must contain at minimum:

`instance_id`
`condition`
`seed`
`S_t`
`T_acc_t`
`available_transformations`
`information_control`
`information_treatment`
`selected_transformation`
`S_t1`
`T_acc_t1`
`Delta_T_acc_t`
`TSDA_descriptors`
`decision_before_future_reveal`
`leakage_checks`
`null_condition`

The schema must separate observed fields from derived fields.

## 12. Independent reconstruction

Executor-2 must reconstruct the frozen package independently from the source specification and integrity manifest.

The reconstruction must verify:

- environment identity;
- state identity;
- current accessibility;
- transformation identities;
- successor states;
- successor accessibility;
- TSDA descriptors;
- condition assignment;
- leakage checks;
- primary metric calculation.

Scientific interpretation is blocked if reconstruction deviations are non-zero.

## 13. Integrity manifest

The preflight package must freeze hashes for:

- environment generator;
- instance dataset;
- treatment/control encoder;
- null encoder;
- randomisation configuration;
- executor scripts;
- schema;
- primary analysis specification.

Any mismatch invalidates the corresponding preflight component.

## 14. Required preflight tests

All tests below must PASS before execution can be considered:

**P1 — Current-space equality:** control and treatment have identical T_acc,t.

**P2 — Candidate multiplicity:** every analysed instance has at least two executable transformations.

**P3 — Treatment specificity:** treatment differs from control only by declared transformation-space information.

**P4 — No direct recommendation:** no treatment field directly encodes a preferred transformation.

**P5 — No outcome leakage:** no treatment field encodes reward, utility or outcome ranking.

**P6 — Future non-derivability:** the treatment-only future-space property is not derivable from control information for anticipation instances.

**P7 — Temporal order:** selection occurs before successor-state/future-space reveal.

**P8 — Null validity:** null information contains no future-space signal or recommendation.

**P9 — Deterministic reconstruction:** independent executor reproduces the frozen records and descriptors.

**P10 — Primary metric freeze:** the primary estimand is fixed before scientific execution.

## 15. Scientific boundary

A PASS on P1–P10 means the experimental package is structurally eligible for scientific execution. It does not constitute evidence for TI.

Execution requires a separate authorisation gate after the preflight audit.
