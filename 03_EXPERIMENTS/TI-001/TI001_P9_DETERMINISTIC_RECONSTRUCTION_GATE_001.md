# TI-001 — P9 Deterministic Reconstruction Gate 001

**Status:** GATE SPECIFICATION — NOT EXECUTED  
**Scope:** P9 — Deterministic reconstruction  
**Scientific execution:** NOT AUTHORIZED

## 1. Purpose

P9 verifies that an independently implemented Executor-2 can reconstruct the frozen TI-001 preflight fixture and its descriptors without importing, executing, parsing, or consuming the canonical Executor-1/generator implementation.

P9 is a reconstruction gate, not a scientific execution.

## 2. Governing specification

The reconstruction is governed by:

`TI001_EXECUTOR_2_RECONSTRUCTION_SPECIFICATION_001.md`

The canonical TI-001 preflight specification defines P9 as:

> Deterministic reconstruction: independent executor reproduces the frozen records and descriptors.

This gate operationalizes that requirement.

## 3. Independence boundary

Executor-2 MUST NOT:

- import `TI001_PREFLIGHT_FIXTURE_GENERATOR_001.py`;
- call the canonical generator;
- execute the canonical generator as a subprocess;
- parse the canonical generator source to derive runtime values;
- consume Executor-1 output as an input to reconstruction;
- copy Executor-1 generated records as reconstruction input.

Executor-2 MAY use only the reconstruction specification, explicitly frozen fixture parameters, and its own implementation.

The frozen canonical fixture is an equivalence target, not an implementation input.

## 4. Reconstruction target

Executor-2 must independently construct:

- 32 pair identifiers;
- the seeded randomisation assignment;
- 64 records;
- all observable deterministic environment fields;
- condition-specific information;
- null information;
- TSDA descriptors;
- leakage checks;
- preflight null execution fields;
- top-level fixture metadata.

The following MUST remain null:

- `selected_transformation`;
- `S_t1`;
- `T_acc_t1`;
- `Delta_T_acc_t`.

No scientific choice or transition is executed.

## 5. Seed semantics

`RANDOMISATION_SEED = 582031` is functionally used to generate the condition assignment.

`ENVIRONMENT_SEED_BASE = 731407` determines the observable per-pair `environment_seed` field.

The canonical generator's internal `_environment_nonce` is discarded and is outside the reconstruction target.

Executor-2 MUST NOT claim that the environment structure is generated by `environment_seed`.

## 6. Equivalence checks

P9 MUST independently verify:

1. schema identity;
2. `randomisation_seed` identity;
3. `environment_seed_base` identity;
4. pair count = 32;
5. record count = 64;
6. pair identifiers;
7. condition assignment;
8. current state and accessibility;
9. available transformations;
10. successor structure;
11. future alternatives;
12. temporal order;
13. primary estimand definition;
14. null information and null condition;
15. condition-specific information;
16. TSDA descriptors;
17. preflight null fields;
18. decision-before-future-reveal flag;
19. leakage checks;
20. canonical JSON serialization equivalence;
21. canonical `fixture_sha256` equivalence.

## 7. Canonical hash rule

The hash input is constructed from the fixture object before adding `fixture_sha256`.

Serialization MUST use:

- UTF-8 encoding;
- lexicographic JSON key ordering;
- separators `(",", ":")`.

The resulting SHA-256 digest is then stored as `fixture_sha256`.

Executor-2 MUST independently reproduce this process.

## 8. Comparison protocol

The gate compares Executor-2 output with the frozen canonical fixture.

The comparison MUST distinguish:

- structural mismatch;
- assignment mismatch;
- record-content mismatch;
- descriptor mismatch;
- serialization mismatch;
- hash mismatch.

A hash mismatch MUST NOT be treated as sufficient evidence of the location or nature of a deviation.

## 9. Scientific boundary

P9 MUST NOT:

- select transformations;
- execute transitions;
- reveal successor states as part of an experimental run;
- calculate a scientific treatment effect;
- interpret TI;
- infer intelligence, value, reward, utility, performance, or causal effects.

P9 establishes reconstruction integrity only.

## 10. PASS criteria

P9 = PASS only when:

- Executor-2 is demonstrably independent under the boundary above;
- all required equivalence checks pass;
- the canonical serialization is identical;
- the reconstructed `fixture_sha256` equals the frozen fixture hash;
- no scientific execution has occurred.

## 11. FAIL criteria

P9 = FAIL if any required equivalence check fails, if independence is violated, if the canonical hash differs, or if scientific execution occurs during reconstruction.

Any FAIL blocks the scientific execution path.

## 12. Evidence package

A completed P9 gate should persist, at minimum:

- Executor-2 source;
- Executor-2 execution record;
- reconstructed fixture or equivalent deterministic output;
- canonical fixture reference/hash;
- comparison report;
- independence attestation;
- environment/runtime metadata;
- P9 PASS/FAIL result.

The evidence package must not contain scientific outcome data because P9 is pre-execution.

## 13. Relation to P10

P9 does not replace P10.

P9 establishes deterministic reconstruction integrity. P10 separately establishes that the primary estimand is frozen before scientific execution.

## 14. Governance disposition

P9 PASS authorizes progression to the remaining pre-execution governance checks only.

P9 PASS does NOT authorize scientific execution.

**Current status: NOT EXECUTED.**
