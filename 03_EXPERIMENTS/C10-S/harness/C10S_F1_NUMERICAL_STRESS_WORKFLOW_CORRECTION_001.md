## 1. Confirmed root cause

The former workflows 001 and 002 both declared `runner.temp` in the job-level `env` mapping:

- `EVIDENCE_ROOT: ${{ runner.temp }}/...`
- `VENV: ${{ runner.temp }}/...`

GitHub's context-availability table does not permit the `runner` context in `jobs.<job_id>.env`. It does permit it in step-level keys such as `steps.with` and `steps.run`. This is a workflow-definition validation error that occurs before a runner job can be materialized.

The same invalid placement was initially carried into consolidated workflow 003. It has now been removed. Runner-local paths are initialized inside a shell step using the runner-provided `$RUNNER_TEMP` environment variable and exported through `$GITHUB_ENV`.

Reference: GitHub Actions — Contexts reference, “Context availability”:  
https://docs.github.com/en/actions/reference/workflows-and-actions/contexts
