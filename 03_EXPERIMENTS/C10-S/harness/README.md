# C10-S focal harness — implementation slice 001

**Scope:** methodological software slice for the focal randomized accessibility-mixture contrast on the synthetic B1 value instance (V_{B1}=Q_{B1}).  
**Status:** IMPLEMENTED_IN_RESEARCH_BRANCH / NOT_EXECUTED / NOT_CONFIRMATORY / NOT_DESIGN_FROZEN.

## Components

- `focal_harness.py`: explicit scenario and analysis contracts; focal DGP; restricted truth bundle; allow-list projector; evidence sealer; Analyzer; Evaluator.
- `test_focal_harness.py`: 15 software-contract tests plus one deterministic P178 bridge test. The bridge feeds a single N=700, balanced 350/350 sample generated by the persisted P178 DGP into the Analyzer and checks estimate, standard error and 95% interval against an independent NumPy/SciPy Welch calculation.

## Separation contract

1. Generator returns three distinct objects: run manifest, restricted `TruthBundle`, and `GeneratedSource`.
2. Projector emits only `unit_id`, randomized assignment, observed `Q_B1`, and observation status.
3. Sealer validates the allow-list and hashes the observed bundle.
4. Analyzer accepts only `SealedEvidence` plus a public `AnalysisContract`; its API has no truth, potential-outcome, signature, seed or generator-parameter argument. Run identity hashes the complete declared scenario configuration, including its parameters and seed.
5. Analyzer reports package ITT and focal-attribution outputs in separate fields. The package ITT estimate/interval remain available when focal attribution is not identified; focal estimate/interval are populated only when all focal identification gates pass.
6. Evaluator receives truth only after Analyzer has returned its result and checks run identity and output seal.

This is an application-level boundary, not a demonstrated security boundary. It does not replace the PE threat model, process/storage separation, effective ACLs, side-channel tests or G-ROLE acceptance.

## Focal DGP

The scenario config requires every parameter; there are no silent numerical defaults. It generates two potential (Q_{B1}) values per unit under (Z=0,1), with a two-state Markov availability process, policy-dependent probability of signature (d1), focal transition effects ((\alpha_{01},\alpha_{10})), and optional direct transition effects ((\gamma_{01},\gamma_{10})).

The focal truth is the analytical contrast under the common direct-path regime (\gamma=0):
[
\theta_A=(\lambda_1-\lambda_0)\{\mu_Q(d1)-\mu_Q(d0)\}.
]
The realized assignment contrast is separately retained as the package ITT truth. Focal attribution is emitted only when the direct path is declared absent, the common regime is established, positivity and version consistency are established, measurement is ideal, and interference is absent. A declared direct path blocks focal attribution; an unknown direct-path status or a failed focal gate forces indeterminacy. Evaluator adjudication applies the same package-level gates before judging focal identification, and separately detects a false declaration of no direct path against DGP truth.

## Explicit limitations

- This slice instantiates only the B1 scalar valuation case (V_{B1}=Q_{B1}); it does not instantiate general vector Value or a general (\Delta T_{acc}\to Value) claim.
- It is not the complete D2 material scenario, full transformation graph/Reach/trajectory reconstruction, full event ledger, missingness/censoring engine, cluster/interference engine, or general U_G store.
- The Analyzer reports a Welch–Satterthwaite two-sided 95% interval for the package ITT difference in arm means. When focal identification gates pass, the same estimate and interval are also explicitly exposed as focal outputs; otherwise focal outputs are null. A deterministic bridge test now checks this calculation against an independent Welch implementation on one finite-sample dataset generated by the P178 DGP. It does not validate Monte Carlo operating characteristics or replace the 10,000-replication P178 benchmark.
- The software tests are not Monte Carlo calibration, scientific execution, confirmatory execution, or evidence for a TGCV claim.

### Focal theta_A Evaluator — reserved-oracle comparison

`theta_a_evaluator.py` adds an independent Evaluator for the sealed direct-`g_A` S3 observation path. It receives the reserved `ThetaAVContTruthBundle` only after Analyzer output exists. It verifies the truth-bundle digest, estimand/outcome identity, q_X fingerprint, evidence digest, Analyzer-result digest, assignment/q_X provenance and the correspondence between observed histories and the reserved EventHistory manifest.

The Evaluator also receives the direct assignment bundle (not the truth oracle's potential outcomes) and verifies exact per-unit arm, assignment probability, joint-vector fingerprint, selected policy fingerprint, baseline-history reference and common-regime binding; aggregate `g_A0`, `g_A1`, `q_X*` and `r_common` fingerprints must agree across the assignment bundle, analysis contract and reserved oracle. The canonical estimand identity is `THETA_A_QX_GA_RCOMMON_VCONT`. For an identified point result, it scores absolute error against the reserved `theta_A` oracle. For partial identification, it checks whether the reported bounds contain the reserved truth and separately marks whether the bounds are informative. For `NOT_IDENTIFIED`/`INDETERMINATE`, it requires a point-estimate abstention and an explicit reason. A bound that excludes the reserved truth is classified as an Analyzer adjudication failure.

The current `POINT_SAMPLE` Analyzer returns the logical contrast bounds [-1,1]. The Evaluator therefore records correct coverage when the oracle lies inside those bounds, while explicitly marking the bounds non-informative; this is not causal recovery. Regression specifications cover point recovery, bound coverage, bounds excluding truth, and evidence/result provenance mismatch. They have not been executed.

### C10-S complete-world composition entrypoint

`c10s_world_pipeline.py` adds `materialize_c10s_complete_world(...)` as the first coordinated composition API for the current synthetic-world components. It materializes the finite target roster and D2 potentials, computes the complete U/R/C/X structural delta for each unit × Z potential, derives baseline/post Reach and potential trajectories, adjudicates the D2 VCONT-B1-MIN potential truth, computes the direct-`g_A` theta_A oracle from its reserved policy EventHistories, randomizes the direct policy assignment, selects the exact realized EventHistory, projects S3, seals the evidence, runs the observation-only Analyzer and performs the independent Evaluator comparison.

The composition requires explicit versioned configs, q_X* masses, joint policies, feasibility support, fixed r_common certificates, temporal grid, both D2 EventHistory potentials and the complete g_A policy-EventHistory support. D2 and g_A histories must share one run identity and bind to the same world/roster. It does not synthesize event transitions from downstream outcomes or infer absent histories. The output retains the exact source bundles and validates their common world/run identity and coverage.

The same component module now exposes `EventHistoryGenerationSpec`, `FunctionalStateChange` and `generate_event_history()`. The generator deterministically materializes ordered functional transitions, state-before/state-after chaining, exact Decimal event times, transition IDs and the independent transition manifest, then validates the complete history. It rejects neutral changes, out-of-support or unordered transitions, and undeclared PROFILE version changes. Crucially, it accepts an explicit functional-state path: it does **not** infer B1 admission from D2 `A_f*`, from a joint-policy vector, from PROCESS_EVENT, or from S3. The scientific DGP mapping from D2/direct-g_A mechanisms to ENABLED/admission states remains an explicit input contract rather than an undocumented assumption. Regression cases are included in `test_c10s_synthetic_components.py` and in the existing EP-02 module closure; they remain unexecuted.

This is an integration API, not yet the final self-contained DGP runner: the EventHistory potential sets are still supplied by the caller, the S3 implementation remains POINT_SAMPLE, and the Analyzer therefore returns non-informative [-1,1] theta_A bounds when both randomized arms and target support are represented. Missing target support or a missing realized arm now produces explicit INDETERMINATE abstention rather than a crash. The Evaluator requires the reserved truth to lie within the reported bounds even when the Analyzer abstains. No tests or experiment have been executed.

## Focal θ_A inference readiness audit — 2026-11-17

This is a source-level audit of the current direct-`g_A` interval-observation path after EP-02. It is not a calibration or scientific result.

### What is implemented

- `generate_theta_a_policy_assignments` assigns one unit to `g_A0` or `g_A1` using an explicit history-specific Bernoulli probability strictly between zero and one. The draw is keyed by the unit and a dedicated randomization salt; Z and the legacy G assignment are not substituted.
- The focal Analyzer uses the sealed interval observations and the declared `q_X*` history masses. With complete certified interval observations and both realized arms represented, it computes a q_X-standardized Horvitz–Thompson contrast. With missing intervals, incomplete target support or an absent realized arm, it abstains.
- The independent Evaluator opens the reserved `theta_A` truth after analysis and checks provenance, point recovery or abstention. It does not feed truth to the Analyzer.

### Exact inferential gap

The focal Analyzer now optionally reports a conservative finite-sample Hoeffding confidence interval for the q_X-weighted Horvitz–Thompson contrast under the **joint two-stage randomization**. For unit/history i, the HT contribution is bounded by `[-q_i/p0_i, q_i/p1_i]`; the reported radius is `sqrt(0.5 * sum_i width_i^2 * log(2/alpha))`, with `width_i=q_i*(1/p0_i+1/p1_i)`. The confidence level is an explicit contract input; no default alpha or precision target is imposed. The second-stage joint-vector draw is included as part of the unit's bounded [0,1] outcome, not conditioned away. The Evaluator independently checks the probability map against the actual assignment bundle and reconstructs the interval from sealed evidence.

This is a conservative bounded-range interval, **not** a design-based standard error, Wald interval, test statistic or p-value. Its coverage guarantee requires explicitly certified unit independence (independent joint randomization including within-policy vector draws, and no cross-unit interference), fixed q_X weights, correct history-specific probabilities, complete interval observation and the declared [0,1] outcome bound. The pipeline refuses to enable the interval unless `theta_a_unit_independence_certified=True` is explicitly supplied alongside the confidence level. It is not calibrated for finite-sample power or useful precision. The two-unit regression fixture checks arithmetic and contract wiring only; it cannot validate empirical coverage, type-I error, power, or operating characteristics under unequal probabilities.

The interval S3 monitor is currently an ideal continuous-coverage channel with independently generated interval missingness. It is not a calibrated imperfect-detection/false-positive model. The point-sample route remains unable to identify strict interval continuity. Neither route establishes robustness to imperfect S3.

### Calibration boundary

The existing 13-scenario × 4-assignment-estimand (52-key) matrix and its seed-bank protocol explicitly exclude `theta_A`; that exclusion must remain intact. The assignment generator also performs a second, within-arm random draw of the joint vector from the selected `g_A` policy distribution. A focal variance contract must account for both the Bernoulli arm assignment and this policy-vector randomization (or explicitly condition on a fixed set of policy draws and state the narrower estimand). A variance formula for the first-stage Bernoulli assignment alone is not automatically valid for the stochastic-policy estimand. The current protocol sizes assignment repetitions `R` for its own estimands and specifies an outer Monte Carlo dimension `M` that is not implemented. Its `required_replicates` function must not be repurposed as an `M` selector or silently transferred to `theta_A`.

### Next implementation block

The first conservative inference contract is now implemented in Analyzer/Evaluator as `HOEFFDING_TWO_STAGE_BOUNDED_HT_V1`. It is intentionally optional until an explicit confidence level and exact history-specific assignment probabilities are supplied. It returns a distinct inferential interval and range-sum diagnostic; the logical parameter bounds `[-1,1]` and measurement-only bounds retain their separate meanings. Missingness, incomplete q_X support or absent realized-arm support suppress the inferential interval rather than silently narrowing the target.

The next calibration design must distinguish units `N`, repeated assignments `R` within a fixed world, and independent outer worlds `M`, with disjoint calibration/evaluation seed domains. It must measure empirical coverage, interval width/precision, type-I error and power (where a test is later specified), point recovery and correct abstention, including unequal history-specific probabilities and policy-vector stochasticity. No standard error or p-value is claimed. Numeric precision targets, candidate grids and budgets remain governed by explicit pre-execution decisions. This method implementation is a source-level change only: no test suite, calibration, seed generation, Monte Carlo or scientific experiment was run.

## Focal θ_A calibration protocol scaffold — 2026-11-17

The focal direct-`g_A` path now has a separate source-level calibration protocol in `theta_a_calibration_protocol.py`, with nine deterministic contract-test definitions in `test_theta_a_calibration_protocol.py`. It is deliberately separate from `vcont_benchmark_protocol.py` and its 13-scenario × 52-assignment-estimand matrix; that protocol explicitly excludes `theta_A` and its RUN/R semantics are not imported as focal estimands.

### N / M / R semantics

- **N:** units in one synthetic world.
- **M:** independent outer worlds, each with a distinct world identity and world seed.
- **R:** repeated direct-`g_A` assignment replicates within one fixed M world. Each R gets a unique `run_id`, joint-policy randomization salt and S3 seed; world identity/seed remain fixed within M.
- There is no extra designated RUN row for `theta_A`: the focal estimator has no run-conditional estimand class.
- The existing assignment generator uses one per-R salt with distinct domain labels for the Bernoulli arm draw and the within-policy joint-vector draw. The second-stage vector draw is therefore varied on every R and remains part of the stochastic-policy estimand, not conditioned away.
- S3 measurement uses a separate per-R seed, expanded deterministically to unit-specific monitor seeds.
- Calibration and evaluation banks are domain-separated and validated for disjoint world, assignment and S3 streams. The capture boundary rechecks the materialized world seed commitment and actual assignment-salt hash; for the continuous interval lane it also verifies each S3 observation ID against the per-R/per-unit monitor seed. R rows must preserve world-configuration and q_X/g_A/r_common design fingerprints while varying assignment, sealed-evidence and Analyzer-output fingerprints. Point-sample S3 is explicitly ineligible for this interval-confidence calibration.

### Captured metrics and fail-closed rules

The aggregator first forms one metric contribution per fixed world M from its R replicates, then estimates Monte Carlo means/MCSE across independent M worlds. It supports interval coverage and width, point bias/MAE/RMSE, point recovery only when an explicit tolerance is supplied, identification/abstention, correct abstention, false identification/abstention and interval availability. Missing R/M contributions or any abstention in a numeric identified-only metric make that metric `NOT_EVALUABLE`; they are not removed from a complete-case denominator.

The scenario contract must supply its expected identification status independently of the Analyzer. It also requires an explicit independence basis for scenarios declared unit-independent. For any such scenario the requested confidence level is retained even when the Analyzer abstains because of missingness or support; interval availability is reported separately rather than dropping those replicates. `PARTIALLY_IDENTIFIED` truth scenarios are deliberately rejected until the measurement-bound procedure is adjudicated; the observed Analyzer status `PARTIALLY_IDENTIFIED` is retained rather than collapsed to another status. Type-I error and power are explicitly `NOT_DEFINED_NO_TEST_PROCEDURE`; the Hoeffding interval is not silently turned into a hypothesis test.
