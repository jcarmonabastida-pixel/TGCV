# TGCV TR-131 — VisitAll Dynamic Transformation Space Package Construction Specification 001

**Status:** PASS — PACKAGE CONSTRUCTION SPECIFICATION / SCIENTIFIC EXECUTION NOT AUTHORIZED  
**Date:** 2026-09-23

## 1. Purpose

Freeze the executable construction for the VisitAll-only Dynamic Transformation Space representation test.

The experiment tests whether explicit, time-indexed transformation-space information

`T_acc,t` and `Delta_T_acc,t`

provides an analytically distinct representation beyond the source-defined baseline transition trace.

This is a representation/falsification test. It is not a causal, value, intelligence, irreducibility, or Core test.

## 3. Depth and enumeration rule

**Frozen exploration depth: 2 realized transformations.**

The runner starts from the locked initial state `S_0`.

At every state:

1. reconstruct `T_acc,t` exclusively from the source-defined state and `connected` relation;
2. freeze the complete accessible set;
3. enumerate every member of `T_acc,t`;
4. realize that grounded move using the source-defined transition adapter;
5. reconstruct `S_(t+1)`;
6. reconstruct `T_acc,t+1`;
7. compute `Delta_T_acc,t`;
8. continue exhaustively until two realized transformations have been traversed.

No sampling, randomization, planner search, goal-directed selection, optimization, or treatment policy is used.

The complete bounded tree, including all admissible branches at depths 0, 1, and 2, is the scientific dataset.

## 4. Transformation-space representation

For each node:

`S_t` = complete reconstructed VisitAll state relevant to the frozen source.

`T_acc,t` = complete set of grounded `move` transformations whose source-defined preconditions hold.

`T_real,t` = the enumerated grounded transformation realized on that branch.

`S_(t+1)` = exact successor generated by the source-defined transition adapter.

`Delta_T_acc,t` = (`Added_t`, `Removed_t`, `Retained_t`) using exact set operations.

Transformation identity is:

`move:<curpos>-><nextpos>`

No semantic labels are added.

## 5. Baseline representation

The baseline for every branch is the same source-defined sequence:

`S_t -> T_real,t -> S_(t+1)`

The baseline must be generated from the same state, action, and transition facts.

The explicit `T_acc,t` and `Delta_T_acc,t` fields are additional analytical projections of those facts; they may not receive any information unavailable to the baseline.

## 6. Prespecified cases

### C2 — same S and T_acc, different realization

At depth 0, all four initial transformations are independently enumerated.

Any two distinct branches therefore begin with identical `S_0` and identical `T_acc,0`, while `T_real,0` differs.

### C3 — different trajectories from equivalent initial S/T_acc

Branches with different first realizations are continued exhaustively to depth 2.

The resulting trajectories are compared while preserving the common `S_0` and `T_acc,0`.

C3 is descriptive only; it is not itself evidence of representational gain.

### C4 — realization-induced subsequent accessibility change

For every depth-0 realized transformation, `T_acc,1` is independently reconstructed from `S_1`.

The experiment records whether and how `T_acc,1` differs from `T_acc,0`.

This is descriptive evidence for transformation-space dynamics. It is not itself a PASS.

C1 remains explicitly excluded because frozen VisitAll semantics make `T_acc` deterministic given `S`.

## 7. Primary comparison

For each branch, construct two synchronized records:

### Explicit representation
`S_t, T_acc,t, T_real,t, S_(t+1), Delta_T_acc,t`

### Baseline representation
`S_t, T_real,t, S_(t+1)`

The comparison asks whether a prespecified distinction in the explicit representation cannot be reconstructed from the baseline without introducing information not already present there.

## 8. Falsification criteria

### FAIL — no distinct representational gain

Report FAIL if all observed `T_acc` and `Delta_T_acc` distinctions are losslessly derivable from the baseline state/action/transition trace.

This result is scientifically informative: it falsifies the claim that explicit transformation-space representation adds an analytically distinct object for this source and bounded test.

### PASS — distinct representational gain

Report PASS only if at least one prespecified distinction is explicitly represented by `T_acc`/`Delta_T_acc` and cannot be recovered from the baseline without adding information or changing its semantics.

### INCONCLUSIVE

Report INCONCLUSIVE if source-defined accessibility, transition semantics, or baseline synchronization cannot be reconstructed deterministically.

## 9. Anti-circularity constraints

The runner MUST NOT:

- use goal achievement to define `T_acc`;
- use future states to define `T_acc,t`;
- use `T_real,t` when constructing `T_acc,t`;
- use trajectory success, outcome, or value;
- introduce X, Pi, THC, intelligence, or capability variables;
- alter source-defined preconditions/effects;
- infer `Delta_T_acc` from an expected result;
- use a planner to determine the branch set;
- import Rainbow or any other domain.
