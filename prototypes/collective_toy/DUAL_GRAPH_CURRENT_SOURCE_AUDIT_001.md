# Dual-graph current-source audit 001

**Status:** source inspection only; no executable changes and no scientific execution.  
**Branch:** design/condition-evaluator-contract-001-20261021  
**Source inspected:** main:prototypes/collective_toy/web/index.html  
**Git blob SHA returned by GitHub:** 6e79802dec5d399638757518dfd2c8b94214613d. The file was fetched from the main ref during this audit. The fetch did not return the current main HEAD commit, so this audit pins the exact file object rather than claiming a verified HEAD commit.

## Scope

Inspect the current browser demonstrator's input model, transition graph rendering, trajectory exploration, concrete execution/value layer, and import/export boundary for the agreed dual-graph design:

1. System graph: states, transitions, and conditions.
2. Separate TGCV graph: transformations, typed relations, accessibility, and trajectories.
3. Explicit mapping/provenance bridge between them.

This is not authorization to implement a condition evaluator, migrate the schema, or change the stabilized TGCV Core.

## Findings verified in the fetched source

### 1. Existing model is a system-transition model

- example() defines collective-toy-input-001 with states, transitions, relations, rule_profile, scenarios, and exploration (file line 49 onward).
- validate(m) (lines 57–73) accepts collective-toy-input-001 and collective-toy-input-002. A transition has id, source, target, and optional condition.
- The existing relations contract is specifically requires_prior_execution, keyed to transition IDs. It is not a generic TGCV transformation-relation model.
- Scenario keys are restricted to id and disabled_transitions; there is no condition context or explicit TGCV model/mapping field.

**Implication:** do not overload existing relations or condition fields to encode TGCV transformations. Add a separately typed model only after the data contract is approved.

### 2. Conditions are displayed, not evaluated

- runTemporalScenario(m,s) (lines 74 onward) creates adjacency only for transitions that are not scenario-disabled and have no condition.
- draw(m,r,sid) (around lines 127–131) labels conditional transitions with “CONDICIÓN NO EVALUADA”.
- Therefore the current exploration engine does not resolve a condition as true/false/unknown; conditional edges are excluded from explored trajectories.

**Implication:** the UI must continue to label this limitation clearly. Do not imply that the system graph's condition labels are executable gates. The condition evaluator remains paused pending a separate decision.

### 3. The current graph renderer is coupled to the system model

- draw(m,r,sid) (starts around line 127) receives the same input model and scenario results generated by the existing engine. It places m.states and draws m.transitions.
- The graph editor (syncGraphEditor, around line 416 onward) edits those same system states and transitions.
- No separate TGCV graph object or explicit mapping records are present in the inspected input model contract.

**Integration point:** retain this renderer/editor as Graph 1. Introduce a distinct Graph 2 renderer and its own model state; do not derive TGCV edges by merely renaming system transitions.

### 4. Trajectories and reachability currently belong to the system graph

- runTemporalScenario builds paths from the system model's states and transitions, enforcing the existing temporal prerequisite relations.
- execute(m) returns scenario results, comparisons to baseline, and the boundary statement “NONE: synthetic model execution only; no empirical or TGCV validity claim.”
- addDeltaReach(m,result) calculates scenario differences using the same system model and trajectory results.

**Implication:** these are useful system-execution outputs, but they are not yet TGCV T_acc, ΔReach, or transformation trajectories. A future TGCV calculation needs separate, explicit semantics and must not relabel these existing outputs as TGCV results.

### 5. Import/export currently targets one model/package

- The graph import path (modelFromEdges / parseGraphText, around lines 420 onward) creates the existing system model from DOT/Mermaid/GraphML edges.
- The JSON import path validates a single model before replacing the editor model.
- The execution path (run, around line 200 onward) packages the input model with engine results, hashes, and execution outputs; the imported-package validator later checks the expected input/result structure and hashes.
- No separately persisted TGCV graph or system↔TGCV mapping is represented in the inspected model contract.

**Integration point:** a future export format must preserve both graph objects, mapping records, provenance, and versions of derivation rules. Backward compatibility for existing single-system-model files should be explicit; do not silently reinterpret old imports as dual-graph packages.

### 6. Existing result/value layer should remain separate

- The browser's concrete execution and value dashboard record a selected system trajectory, its explicit outcome, and a contextual assessment (observer, context, criterion, valuation rule).
- The engine explicitly disclaims empirical or TGCV validity. A perceived-value score is a contextual assessment, not a demonstrated causal consequence of ΔT_acc.

**Implication:** preserve the outcome/observer/context layer as a separate later stage. Do not wire it directly to a new TGCV graph as a causal claim.

## Recommended integration map

| Area | Existing component | Target treatment |
|---|---|---|
| Graph 1 | draw, syncGraphEditor, validate, runTemporalScenario | Preserve as system graph and system execution |
| Graph 2 | No distinct component found in inspected model/render path | Add separate TGCV graph model and renderer after contract approval |
| Mapping bridge | No explicit mapping records in input schema | Add typed records with provenance: user_declared, rule_derived, illustrative, unresolved |
| Accessibility | Existing system reachable_states / scenario deltas | Keep separate from TGCV T_acc and ΔReach; specify TGCV semantics first |
| Conditions | condition string displayed as unevaluated and omitted from exploration | Keep evaluator paused; decide semantics and truth/unknown handling separately |
| Import/export | Single system model and execution package | Define versioned dual-graph persistence and legacy compatibility |
| Value | Explicit outcome and contextual assessment | Preserve as distinct layer; no direct causal claim |
