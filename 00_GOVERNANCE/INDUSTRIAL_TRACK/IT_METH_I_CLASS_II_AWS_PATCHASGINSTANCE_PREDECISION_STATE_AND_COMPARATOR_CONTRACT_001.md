## 1. Purpose

Define, before any execution, the minimum common pre-decision state and comparator contract required to test whether `AWS-PatchAsgInstance` changes the accessible transformation structure relative to an ordinary patching path.

This is a methodological fixture design. It does not constitute AWS deployment authorization or industrial-case evidence.

## 2. Common pre-decision state

Both candidate and comparator must start from the same frozen state and evidence boundary.

### Required state variables

1. ASG identity and immutable source/reference.
2. Target EC2 instance identity.
3. ASG desired/min/max capacity.
4. Launch-template identity/version.
5. Effective AMI/image identity.
6. Instance OS identity.
7. Instance health state immediately before decision.
8. ASG lifecycle state and relevant lifecycle hooks.
9. Health-check type and replacement/termination behavior relevant to the target.
10. Patch Group tag state.
11. Effective patch baseline identity/version and assignment.
12. Pre-decision patch compliance state.
13. Systems Manager managed-instance state relevant to patch execution.
14. Candidate and comparator eligibility predicates.
15. Timestamp defining the pre-decision observation cutoff.
16. Frozen evidence manifest and provenance for all variables.

A variable is closed only if its value is directly observable or independently reconstructable at the cutoff. It must not be populated from a post-decision outcome.

## 3. Candidate transformation

Candidate transformation:

`T_candidate = AWS-PatchAsgInstance(InstanceId, frozen parameters)`

The documented runbook parameter vector is frozen as follows unless an amended design record explicitly changes it:

- `InstanceId`: concrete target instance, required at execution time;
- `AutomationAssumeRole`: explicit value if used, otherwise documented omission;
- `LambdaRoleArn`: explicit value if used, otherwise documented omission;
- `WaitForInstance`: `PT2M` unless explicitly frozen otherwise;
- `WaitForReboot`: `PT5M` unless explicitly frozen otherwise.

The transient `AutoPatchInstanceInASG` tag is treated only as execution-control state, never as patch-compliance evidence.

## 4. Comparator contract

The comparator must represent an ordinary patching transformation applied to the **same target state**, under the same evidence boundary, without access to information generated by the candidate execution.

Minimum comparator requirements:

- same target instance or an equivalently frozen target under a separately reproducible reconstruction;
- same OS/image state;
- same effective patch baseline and patch-group state;
- same pre-decision compliance state;
- same temporal cutoff definition;
- same required access evidence;
- no post-decision outcome used to define comparator eligibility;
- operationally explicit transformation identity, not merely a label such as “normal patching”.

The comparator is invalid if it differs in initial state, evidence availability, or decision-time information in a way that could itself explain the measured difference.

## 5. Accessibility contract

For each transformation, accessibility must be evaluated only from information available at the common cutoff.

Represent accessibility as a vector of explicit predicates:

`A(T | S_t, E_t) = (a_1, a_2, ..., a_n)`

where each predicate is tied to an observable state/evidence variable.

A difference is admissible only when at least one predicate differs between candidate and comparator before execution, or when the transformation identity itself produces a demonstrably different accessible transformation structure from the same state.

A difference discovered only after execution is not an accessibility distinction.

## 6. Primary experimental object

The primary object is the pre-decision transformation structure:

`T_acc(S_t, E_t)`

The experiment asks whether:

`T_acc^candidate(S_t, E_t) != T_acc^comparator(S_t, E_t)`

under a common frozen state/evidence boundary.

Observed post-decision outcomes may be recorded as downstream observations where appropriate, but they cannot be used to define the pre-decision accessibility state.

## 7. Required metric contract

The metric must be frozen before execution and must be capable of distinguishing candidate and comparator at the decision boundary.

Minimum admissibility condition:

- metric operates on pre-decision variables and transformation accessibility;
- metric does not require post-decision outcomes to establish the initial distinction;
- metric is reproducible from the frozen evidence package;
- metric has an explicit interpretation and comparison rule.

No utility score is assigned by this design record.

## 8. Independent reconstruction contract

Two independent reconstruction paths must consume the same frozen source package and reproduce the pre-decision state representation independently.

They must agree on:

- state variables;
- variable values;
- evidence provenance;
- accessibility predicates;
- candidate transformation identity;
- comparator identity;
- temporal cutoff.

Material disagreement blocks execution/analysis until resolved under governance.

## 9. Closure criteria

This design becomes execution-ready only when all of the following are frozen:

- complete candidate parameter vector;

- ex-ante metric;
