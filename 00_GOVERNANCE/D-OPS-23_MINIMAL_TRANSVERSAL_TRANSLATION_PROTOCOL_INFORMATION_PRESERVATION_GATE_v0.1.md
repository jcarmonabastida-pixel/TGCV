## 3. Minimal translation protocol

For a native domain construct K at analytical level L, translation requires the following typed mapping where the native domain permits it:

1. **S — system/state carrier:** identify the minimal system state required to evaluate transformations.
2. **C — contextual/conditioning variables:** identify conditions relevant to admissibility but not part of S when analytically separable.
3. **L — law/rule/constraint layer:** identify independently specified rules, constraints, resources and admissibility semantics.
4. **U_tau — candidate transformation universe:** enumerate candidate transformations independently of which transformations were observed or executed.
5. **tau — canonical transformation identity:** specify the minimal identity sufficient to distinguish one candidate transformation from another.
6. **P_tau(S,C,L):** evaluate pre-execution admissibility without using execution, outcome, future activity, reward, success or value.
7. **T_acc:** construct the exact set `{tau in U_tau | P_tau=1}`.
8. **Delta T_acc:** compare canonical membership sets across declared states/times.
9. **Reach:** represent downstream successor states/configurations generated by accessible transformations; do not identify Reach with T_acc.
10. **Trajectory:** represent ordered or explicitly unordered downstream paths only when ordering semantics are independently justified.
11. **Outcome:** represent downstream observed result separately from accessibility.
12. **Value:** represent contextually evaluated utility/value separately from Outcome.

A domain may mark an element **N/A** only with an explicit semantic justification. N/A is not permission to substitute a different construct silently.

## 4. Translation invariants

The following distinctions are mandatory invariants:

- I1: S != tau.
- I2: U_tau != T_acc.
- I3: accessibility != execution.
- I4: T_acc != Reach.
- I5: Reach != Trajectory.
- I6: Outcome != Value.
- I7: P_tau cannot consume downstream Outcome/Value or future activity.
- I8: observed transformations cannot define U_tau when independence is being tested.
- I9: domain-specific native semantics must be preserved in a traceable mapping layer.
- I10: translation must not change the canonical Rust operationalization.

## 5. Non-triviality / anti-renaming test

A translation is classified **TRIVIAL** if every TGCV object is merely a one-to-one label replacement for an already existing native object with no new typing, comparison or separation capability.

A translation is classified **NON-TRIVIAL** if at least one of the following is demonstrated without changing the native evidence:

- a native possibility/action space is separated into candidate universe versus currently admissible subset;
- accessibility is separated from actual execution;
- transformation identity is separated from successor-state identity;
- Delta T_acc can be compared independently from Delta Reach;
- downstream Reach, Trajectory, Outcome and Value can be kept analytically distinct;
- the same typed comparison can be applied to heterogeneous native constructs without collapsing their domain semantics.

D-OPS-22 already established a bounded architectural PASS for this non-triviality condition. D-OPS-23 freezes the protocol; it does not claim that every domain satisfies it empirically.

## 6. Information-preservation test

For each translation, the following information must remain recoverable:

A. native state identity;
B. native transformation/action identity;
C. rule/constraint source;
D. accessibility decision and its inputs;
E. membership of T_acc;
F. temporal comparison basis;
G. successor-state identity;
H. trajectory ordering semantics or explicit absence of ordering;
I. outcome provenance;
J. value/evaluation context.

Failure of any mandatory item without a justified N/A classification means the translation is **NOT INFORMATION-PRESERVING**.

## 7. Hidden-assumption audit

The following are prohibited hidden assumptions:

- equating observed actions with U_tau;
- defining P_tau from observed success/failure;
- defining accessibility from future states or outcomes;
- treating all mathematically possible operations as automatically admissible;
- importing a domain-specific resolver, optimizer or policy without recording it in L;
- replacing exact membership comparison by cardinality;
- inventing temporal ordering where the source does not provide it;
- using value or reward to classify accessibility.

Any required domain-specific assumption must be explicitly frozen in L and exposed in the translation trace.

## 8. Cross-domain translation trace

Every future application must produce a trace with at least:

`native_construct -> TGCV_object -> semantic_definition -> evidence_source -> assumptions -> admissibility_rule -> canonical_identity -> transformation_membership -> downstream_mapping -> unresolved_items`

This trace is the minimum provenance object for claiming a legitimate TGCV translation.
