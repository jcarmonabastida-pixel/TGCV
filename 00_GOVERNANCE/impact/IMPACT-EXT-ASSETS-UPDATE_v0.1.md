# IMPACT-EXT-ASSETS-UPDATE v0.1

**Date:** 2026-09-08  
**Status:** ACCEPTED — CONTROLLED EXTERNAL-ASSET UPDATE OPERATION OPENED  
**Trigger:** DR-045 / governance propagation closure  
**Scope:** external deliverable layer only.

## 1. Trigger and rationale

The current scientific state of TGCV has materially advanced beyond the state represented by the existing external deliverables. The current RMA therefore identifies those deliverables as dependent assets requiring controlled revision.

This operation does not alter the scientific Core, empirical evidence, claim matrix or gate definitions. It propagates the already accepted state into the external communication layer.

## 2. Affected assets

The following current deliverable families are affected:

1. TCP — updated situational version required.
2. Vision Paper — updated situational version required.
3. Research Prospectus — updated situational version required.
4. ARM — updated situational version required.
5. RII — updated situational version required.

Historical versions remain immutable.

## 3. Update principle

Each new version must derive from the current canonical state, including:

- current TGCV architecture;
- current SLR/prior-art boundary;
- current Evidence-to-Claim Matrix;
- current RMA;
- TR-131, RUST-DYN-1 and RUST-DYN-2 bounded evidence;
- D-OPS-21/22/23 contribution boundary;
- current open hypotheses and unresolved gates.

No external deliverable may upgrade an evidence level, originality claim, causal claim, predictive claim, value claim or transversal-validity claim merely through editorial revision.

## 4. Versioning rule

New versions are additive and versioned. Existing historical versions are not overwritten.

The first objective is a **current-state situational baseline**, not a final publication-ready version.

## 5. Industrial Opportunities Map

The Industrial Opportunities Map (MOI) is not required as part of this immediate update batch.

A first `MOI v0.1` should be created later when the programme reaches a sufficient maturity threshold to distinguish plausible industrial opportunity from speculative application projection.

Its creation must therefore be governed by a separate explicit operation/gate and must use the then-current evidence, domain-discovery state and application boundary.

## 6. Proposed execution sequence

### EXT-UPD-1
Historical reconstruction of each existing external asset.

### EXT-UPD-2
Current-state delta analysis against RMA v0.3 and current claim matrix.

### EXT-UPD-3
Controlled drafting of new versions without overwriting historical versions.

### EXT-UPD-4
Cross-asset consistency review.

### EXT-UPD-5
Update RMA traceability and STATUS to identify the new versions as current.

### EXT-UPD-6
Run structural governance validator and perform human consistency closure.

Only after closure is this operation considered complete.

## 7. Non-effects

This operation does not:

- reopen TR-131;
- reopen RUST-DYN-1 or RUST-DYN-2;
- modify the Core;
- modify the Evidence-to-Claim Matrix except where the new asset versions require their already-established claim references to be represented;
- authorize D-OPS-24 execution;
- create or imply an industrial use case;
- establish originality or superiority.

## 8. Consequence for D-OPS-24

D-OPS-24 remains the next scientific controlled operation after the external-asset update closure, unless a substantive result from the update operation creates a new governance dependency.
