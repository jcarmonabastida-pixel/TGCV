# EXT-UPD-4.5 — C-01 Gate-D Alternative Operationalization Decision v0.1

**Date:** 2026-09-09
**Status:** CLOSED / GOVERNANCE DECISION
**Predecessor:** EXT-UPD-4.2 / EXT-UPD-4.4

## 1. Decision

C-01 is retained as bounded evidence of translation of the TGCV Core.

The Gate-D result remains:

`INDETERMINATE — EXTENSION BOUNDARY IDENTIFIED`

Before opening the alternative second-domain route, TGCV will attempt **one new, separately designed operationalization pathway within C-01** for the downstream chain:

`ΔT_acc → ΔReach → ΔTrajectory → Outcome → Value`.

If that controlled pathway cannot establish the required downstream links without violating the frozen TGCV invariants, the second-domain route becomes the next candidate path for consideration under a new explicit governance decision.

## 2. Rationale

C-01 already passed Gates A-C. Gate D did not fail because the Core translation was contradicted; it remained indeterminate because the source and the first operationalization route did not provide sufficiently independent constructions of Reach, Trajectory and Value.

A new operationalization pathway can therefore distinguish two possibilities:

1. the boundary is primarily methodological/operational and can be resolved by a better construction of the downstream objects; or
2. the boundary reflects a deeper limitation of extending the current TGCV architecture through the full downstream chain in this domain.

Testing this distinction within the already established C-01 evidence base is scientifically preferable before spending additional cross-domain discovery budget.

## 3. Scientific invariants preserved

The new pathway MUST preserve:

- Core ontology `S`;
- `T_acc = F(S,C,L)`;
- `ΔT_acc` as the central analytical phenomenon;
- `I` as explanatory mechanism, not Core primitive;
- observed transition ≠ accessible transformation;
- observed trajectory ≠ generated/admissible trajectory set;
- accessibility independent of downstream outcome/value;
- native construct ≠ TGCV object unless semantic equivalence is demonstrated;
- Outcome ≠ Value;
- no causal inference from temporal order alone;
- unresolved/empty cases remain representable;
- no silent strengthening of claims.

## 4. What is authorized now

Only **design, audit and preflight** of a new C-01 Gate-D operationalization pathway is authorized.

The design must specify:

- the alternative construction principle;
- D1 Reach and `ΔReach` operational rules;
- D2 generated/admissible Trajectory and `ΔTrajectory` rules;
- D3 independent Outcome definition;
- D4 independent native Value criterion;
- temporal ordering;
- outcome/value blindness for upstream construction;
- non-collapse and non-circularity tests;
- constructive examples or formal representations sufficient to test the rules;
- evidence hierarchy and provenance;
- PASS / INDETERMINATE / FAIL decision rules;
- explicit stop condition.

Execution requires a separate authorization after design audit and preflight.

## 5. Prohibited at this stage

No:

- execution of the new pathway;
- new dataset acquisition or processing;
- second-domain search;
- new D-OPS candidate-family search;
- causal inference;
- predictive testing;
- value optimization;
- universal-validity claim;
- originality/superiority claim;
- modification of the TGCV Core;
- retroactive reinterpretation of C-01 Gates A-C;
- update of `05_ASSETS`.

## 6. Fallback condition

If the new C-01 pathway reaches a controlled result of `INDETERMINATE` or `FAIL` for the same extension boundary, the result must be propagated through the Evidence→Claim Matrix and current RMA before any second-domain operation.

Only then may a new governance decision authorize the second-domain route.

The second-domain route is therefore **reserved, not yet authorized**.

## 7. Epistemic boundary

This decision does not establish full downstream conformance. It does not upgrade C-01 beyond bounded Core-translation evidence.

The purpose of the new pathway is diagnostic: determine whether the Gate-D boundary can be resolved by a materially different operational construction while preserving the scientific invariants.

## 8. Next controlled operation

**D-OPS-24 / C-01 Gate-D alternative operationalization design.**

After design, the mandatory sequence is:

`design → design audit → preflight → explicit execution authorization → execution → Evidence→Claim impact → Matrix → RMA → STATUS → Traceability → CHANGELOG → validator → consistency closure`.

Only after this pathway is exhausted may the second-domain option be considered as the next controlled route.
