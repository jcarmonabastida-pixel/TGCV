# TGCV VIATRA Runtime Trace Instrumentation & Provenance Feasibility Review

**Status:** FEASIBLE WITH DESIGN CONSTRAINTS — no scientific execution authorized  
**Date:** 2026-10-02  
**Candidate:** Eclipse VIATRA  
**Source revision:** `ffa111dbb160c0bc55e89ea16430e97a38908662`

## Purpose

Determine whether VIATRA can support an independent, immutable runtime observation layer capable of measuring temporal organisation of executed transformations without reconstructing that organisation from the transformation-space representation.

## Proposed observation boundary

For each executed transformation event (e_i), the instrumentation layer must emit an immutable record containing:

- run identifier;
- monotonic sequence number assigned by the observer;
- observer timestamp;
- immutable source/runtime revision;
- instrumentation revision;
- transformation identity;
- activation identity;
- pre-state digest;
- post-state digest;
- explicit state-observation boundary;
- event type;
- provenance pointer;
- completeness status.

The primary temporal relation is then defined from the observer sequence/timestamp layer, not inferred from (U_t), (T_{acc}), adjacency, closure, or activation-conflict structures.

## Feasibility mapping

| Requirement | Feasibility | Constraint |
|---|---|---|
| Immutable source revision | FEASIBLE | Freeze exact Git revision and execution dependencies. |
| Transformation event capture | FEASIBLE | VIATRA exposes runtime/debug callbacks around activation selection and firing. |
| Independent event ordering | FEASIBLE | Add an external observer sequence number; wall-clock time is secondary metadata. |
| Pre/post state observation | FEASIBLE WITH CONSTRAINTS | Capture state digests at explicit before/after boundaries; define canonical serialization. |
| Transformation identity | FEASIBLE WITH CONSTRAINTS | Freeze an observer-level identity independent of outcomes. |
| Provenance | FEASIBLE | Bind every event to run, source revision, instrumentation revision and artifact. |
| Completeness | FEASIBLE WITH CONSTRAINTS | Require declared event count and terminal completeness certificate. |
| Separation from (U_t) | FEASIBLE | Do not derive temporal fields from the Rust/package dependency representation. |
| Outcome/value firewall | FEASIBLE | No reward, utility, value or downstream outcome fields in the primary trace schema. |

## Critical design constraint

The observer sequence number is the primary temporal ordering variable. It must be generated by the instrumentation observer at event capture and must not be reconstructed retrospectively from transformation identifiers, activation sets, graph topology, or state-space adjacency.

The observer may record wall-clock timestamps, but timestamps must not be the sole ordering mechanism because clock resolution and concurrency can introduce ambiguity.

## R* operational candidate

For a run (r), define:

[
R^*_r(e_i,e_j) iff seq(e_i) < seq(e_j)
]

with the explicit caveat that this is an **observed execution-order relation**, not yet evidence that execution order is an ontologically fundamental TGCV relation.

A later discrimination test must determine whether the observed relation contains information not reconstructible from the inherited representation (A).

## Independence test

Before admission, construct paired runs with the same inherited transformation-space representation (A), while varying only the controlled execution schedule/conditions permitted by the experimental design.

The observer must be capable of distinguishing:

1. A-EQUIVALENT: observed temporal organisation fully reconstructible from A;
2. A-NON-EQUIVALENT: observed temporal organisation differs while A remains fixed;
3. UNDERDETERMINED: instrumentation or design cannot establish the distinction;
4. NON-DISCRIMINATING: candidate R* adds no measurable discrimination.

No outcome/value variable is permitted in this test.
