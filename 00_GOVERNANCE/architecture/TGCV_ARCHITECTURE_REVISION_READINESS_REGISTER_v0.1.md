# TGCV — Architecture Revision Readiness Register v0.1

**Status:** CURRENT GOVERNANCE REGISTER / NO EXPERIMENT AUTHORIZATION
**Date:** 2026-10-01
**Decision:** ARCH-TRANS-001

## 1. Purpose

Define the evidence package required before the canonical Core or Evidence→Claim Matrix may be revised as a consequence of the architectural transition.

This register prevents both premature architectural replacement and indefinite retention of an architecture after reproducible evidence has shown that its representational boundary is insufficient.

## 3. Required readiness package

A Core revision may enter formal review only when all mandatory components below are available.

### RR1 — Explicit candidate object

A candidate B object has a stable operational identity and is not merely a renamed A variable.

### RR2 — Independent measurement basis

The object is measurable using a frozen, outcome-independent rule with an inspectable provenance.

### RR3 — A-reconstruction failure

The object is reproducibly non-reconstructible from the frozen A representation and its admissible auxiliary vocabulary.

### RR4 — Observation parity

A and B receive equivalent relevant information; the result is not created by giving B additional privileged observations.

### RR5 — Controlled architectural discrimination

A pre-specified test produces an outcome classified as AGAINST-A or an equivalent formal finding that A is insufficient for the declared phenomenon.

### RR6 — Replication / robustness

The architectural distinction survives an independent replication or materially distinct operationalisation.

### RR7 — Scope relevance

The demonstrated insufficiency concerns the phenomenon within the declared scope of the Core, rather than an unrelated or deliberately out-of-scope task.

### RR8 — Anti-post-hoc integrity

Object definition, admissibility rules, measurement, reconstruction criterion and interpretation were frozen before the discriminating observation.

### RR9 — Claim-impact mapping

Each affected Evidence→Claim Matrix claim is mapped from old formulation to proposed formulation, with the exact evidence and reason for change documented.

### RR10 — Independent governance review

A separate architectural review records whether the accumulated evidence warrants a Core revision. Scientific evidence and governance decision remain distinct.

## 4. Readiness states

### NOT READY

One or more mandatory requirements are absent.

### READY FOR ARCHITECTURAL REVIEW

All mandatory evidence components are complete and traceable, but no revision has yet been approved.

### ARCHITECTURE REVISED

A formal governance decision has approved a new canonical Core, with synchronized Matrix/RMA updates and historical preservation of the previous architecture.

## 6. Revision rule

No Core or Evidence→Claim Matrix revision may be justified solely by:

- a successful implementation of a dynamic representation;
- better predictive performance without architectural non-equivalence;
- a single experiment;
- terminology changes;
- a newly introduced variable that was not admissible under the frozen transition rules;
- a result obtained without observation parity;
- an unreplicated architectural distinction.

## 7. Historical preservation rule

When and only when a revision is approved, the prior Core and Matrix versions remain immutable historical records. The new canonical versions must explicitly map their changed concepts and claims to the evidence that triggered the revision.
