# TGCV — D-OPS Formal-to-Empirical Bridge Audit 001

**Status:** CLOSED — BRIDGE NOT ESTABLISHED  
**Date:** 2026-10-01  
**Purpose:** determine whether a controlled formal planning domain can be legitimately paired with a longitudinal empirical source while preserving canonical transformation identity and structural relation semantics.

## 1. Audit boundary

This audit follows the Transformational Dynamics Freeze / Operational Instantiation Gate 001.

It is not an execution authorization and does not modify the TGCV Core, RMA, Evidence-to-Claim Matrix, or claim status.

The test is specifically whether the formal and empirical layers can share the same transformation object without deriving the formal object retrospectively from the empirical outcomes.

## 2. Bridge requirements

A valid bridge requires all of:

1. an independently governed formal rule layer defining the transformation vocabulary and structural relations;
2. an empirical source with longitudinal system states;
3. stable identity linking the formal transformations to empirical system states;
4. a pre-specified mapping between formal and empirical representations;
5. no use of future execution, outcome, trajectory, or success to define the formal transformation object;
6. a structural null and state-reducibility test that can be instantiated on the empirical source.

A bridge that merely extracts a PDDL representation from observed demonstrations is insufficient because the formal layer then inherits the empirical observation process.

## 3. Candidate A — UniDomain / real-robot demonstrations

The publicly described UniDomain resource contains real-robot demonstrations and executable PDDL representations extracted/constructed from those demonstrations. The project reports 12,393 demonstrations and a unified symbolic representation containing operators, predicates and causal edges. The associated public dataset includes tutorial videos, atomic domains, unified domains, tasks and evaluation results. citeturn0search4turn0search6turn0search10

### Formal layer

PASS — a finite symbolic representation with explicit operators/predicates can be obtained.

### Longitudinal empirical layer

PASS/CONDITIONAL — the demonstrations contain temporal sequences of observed robot behaviour and the project explicitly uses videos to derive state transitions. citeturn0search6turn0search10

### Independent formal-to-empirical identity

FAIL for the required bridge.

The PDDL representation is itself derived from the demonstrations. Consequently, using the extracted operators/predicates as an independently governed definition of the transformation space and then testing those same demonstrations as the empirical longitudinal source would make the formal object partly endogenous to the evidence being tested.

This is a representation-learning/data-construction pipeline, not an independently specified formal rule layer followed by an external empirical observation.

### Information firewall

FAIL for a strict confirmatory bridge unless the domain specification can be frozen independently before selecting/evaluating the empirical demonstrations.

### Disposition

**NOT ADMITTED AS CONFIRMATORY EMPIRICAL BRIDGE.**

It remains a potentially useful **methodological development source** for testing parsing, canonical identity, and representation machinery, but not as independent evidence for Transformational Dynamics.

## 4. Candidate B — Classical PDDL benchmarks plus external robot demonstrations

A stronger architecture would use a PDDL domain specification as the formal rule layer and a separately collected robot dataset using the same domain semantics.

The available benchmark repositories provide reproducible PDDL domains and problems, but the benchmark instances are not themselves longitudinal observations of an independently evolving real system. citeturn0search1turn0search2

The audit did not identify evidence sufficient to establish a public longitudinal robot archive whose states are generated independently under the exact same frozen PDDL transformation semantics.

**Disposition: NOT ESTABLISHED.**

## 5. Candidate C — PDDL planning execution traces

A planner can generate complete state/action traces from a frozen PDDL problem. Such traces are formally reproducible and can test `Ω_T` construction and `Γ_t`.

However, these are simulated/formal trajectories generated by the same rule system. They therefore constitute **formal conformance evidence**, not an independent empirical longitudinal source.

**Disposition: FORMAL-ONLY.**

## 6. Key methodological result

The audit identifies a three-layer distinction:

1. **Formal conformance:** a rule system can define a finite transformation space and its structural transitions.
2. **Empirical reconstruction:** a longitudinal source can show changes in a system representation.
3. **Independent bridge:** the formal transformation semantics are fixed independently and then applied to the empirical source without deriving them from that source.

Current public candidates can satisfy (1), and some can approach (2), but the audit found no execution-ready candidate satisfying all three simultaneously.

This is not evidence that such a bridge is impossible. It is a documented failure to establish one from the currently identified public candidates.

## 7. Decision

**D-OPS FORMAL-TO-EMPIRICAL BRIDGE 001 = CLOSED — NO VALID INDEPENDENT BRIDGE ESTABLISHED.**

No empirical execution is authorized.

The external-domain search should **not** continue as an unconstrained candidate hunt. Any future candidate must first demonstrate the independent formal/empirical bridge contract before acquisition or execution work.

## 8. Consequence for Transformational Dynamics

The formalization v0.3 remains a coherent development target, but it is not yet empirically frozen.

The evidence base currently supports:

- formal identifiability as a methodological possibility;
- bounded partial real-world reconstruction in MT5;
- condition-sensitive structural evidence in prior TI-001 work;
- methodological calibration from NEXT4.

It does **not** support claiming that `Ω_T` has already been empirically validated as a general dynamic object.

## 9. Next controlled operation

The next authorized operation is **not another broad domain search**.

It is a **Formal Conformance Test Design**: specify a minimal, fully controlled formal environment in which v0.3 can be instantiated, representation invariance and structural-null tests can be executed, and all failure criteria can be measured.

That test must be explicitly labelled **formal/conformance**, not empirical cross-domain validation.

**REAL-DATA EXECUTION AUTHORIZED: NO.**
