## 4. N/R/M applicability by temporal level

| Temporal level | N | R | M | Required output |
|---|---|---|---|---|
| RUN numeric | Required | Not applicable to the single-run estimate | Required for aggregate benchmark-performance summaries | Error/recovery and identification state |
| RUN status-only | Required for the generated run and status decision | Not applicable | Required for aggregate status rates | Identification/abstention adjudication |
| REPEATED_ASSIGNMENT numeric | Required for every assignment dataset | Required | Required for aggregate performance summaries across independent outer replications | Marginal/reference estimate, truth, error/recovery |
| REPEATED_ASSIGNMENT status-only | Required for every assignment dataset | Required for repeated status-rate precision | Required for aggregate status rates across independent outer replications | Status counts/rates; no numeric error |

The same N and R values may be shared across pairs only if their applicability, precision targets and support conditions are shown to be compatible. A common value is not evidence of common sufficiency.

**M is required as an outer aggregation dimension for benchmark-performance uncertainty but is not implemented in the current seed scaffold.** The existing fixed world seed across R assignment repetitions implements the within-world repeated-assignment structure; it does not provide independent outer M replications.

## 6. Design requirements and unresolved choices

### 6.1 Requirements that follow from the current matrix

1. All 52 pair keys must be present in the coverage inventory for the declared scenario and estimand versions.
2. All 13 reference-regime RUN records must remain status-only.
3. Mechanism-marginal and reference-regime numeric outputs must be produced only at the repeated-assignment level.
4. Measurement-adverse and interference pairs remain status-only; they are not silently dropped from coverage or converted into numeric failures.
5. The three non-identifiable pairs remain in coverage and are adjudicated through identification/abstention, not numeric recovery.
6. The support-failure scenario's reference-regime pair is evaluable only under the DGP-declared total-effect transportability condition already encoded by the current matrix contract; the interaction support-failure reference pair is not identified.
7. Missing/invalid records retain explicit coverage and validity denominators. They are not removed from the denominator or relabelled as abstentions.
8. The same scenario/estimand/version/temporal-level identity must be preserved through Generator, TruthBundle, Analyzer, Evaluator and aggregate reports.

### 6.2 Decisions deliberately left open

No numeric or scientific design value is inferred from current defaults, test fixtures or historical proposals. The following remain OPEN:
- candidate N grid and pair-specific or justified shared N targets;
- R calibration budget/stopping rule and pair-specific or justified shared R targets;
- M outer-replication budget/stopping rule and MCSE targets;
- MCSE targets by metric and temporal level;
- recovery tolerances and minimum relevant effect scales;
- confirmatory subset, if any, and the rationale for excluding other required pairs;
- inferential procedure for coverage, type-I error and power;
- operational definition of independent outer replications and the associated seed/manifest schema;
- handling of any scenario-specific feasibility failure without changing the target estimand.

No parameter may be selected by inspecting confirmatory evaluation outcomes.

## 7. Implementation gaps exposed by the inventory

1. **M identity absent:** the current seed assignment schema has scenario/version, N, assignment replicate and world/Z/G seeds, but no explicit outer Monte Carlo replicate ID.
2. **M aggregation absent:** current summaries can aggregate supplied estimates/rates, but do not prove that inputs are independent outer replicates.
3. **Three-way sufficiency absent:** existing N selection and R sizing helpers do not yet produce a joint N/R/M sufficiency record.
4. **Temporal coverage expansion absent:** the 52-pair matrix defines pair-level classes and RUN/REPEATED classes; a complete 65-record temporal coverage manifest and MONTE_CARLO aggregation key still need explicit implementation.
5. **Shared design values unapproved:** no numeric N/R/M or precision targets have been frozen.

These are implementation requirements, not permission to run calibration or experiments.
