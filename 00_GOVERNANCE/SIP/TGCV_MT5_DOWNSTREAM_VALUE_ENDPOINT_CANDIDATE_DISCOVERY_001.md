# TGCV — MT5 Downstream Value Endpoint Candidate Discovery 001

**Date:** 2026-09-17  
**Status:** `CURRENT_INDEPENDENT_ANALYSIS`  
**Programme:** TGCV — Teoría de Construcción de Valor de Sistemas Generativos

## 1. Purpose

Advance the authorized MT5 analysis by identifying candidate downstream Value endpoints without assuming that conventional outcomes are TGCV Value and without establishing the open relation `ΔT_acc → ΔV` as a methodological or causal rule.

This artifact records the next analytical movement after canonical governance validation (`GOVERNANCE_CURRENT_STATE=PASS`). It does not modify Core ontology, claim statuses, RMA, Evidence→Claim Matrix, or canonical pointers.

## 2. Research boundary

The preserved downstream chain is:

`S_t → Uτ → Pτ → T_acc,t → ΔT_acc → executed transformation → subsequent state / trajectory → outcome → ΔV`

The present task is restricted to the identification and characterization of observable candidate endpoints for `V`.

The following substitutions are prohibited:

- observed transformation ≠ accessible transformation;
- outcome ≠ Value automatically;
- trajectory variable ≠ TGCV trajectory automatically;
- operational performance ≠ Value automatically;
- temporal association ≠ causal effect;
- domain-specific welfare/economic/functional measures ≠ TGCV Value without an explicit value interpretation.

## 3. Candidate endpoint families

### V1 — Economic endpoints

Examples include cost, benefit, productivity, return, total cost of ownership, or other explicitly monetized consequences.

**Potential use:** direct downstream comparison when the economic construct is independently defined and temporally downstream.

**Primary risk:** the endpoint may incorporate assumptions, prices, external shocks, or optimization criteria that are not attributable to the transformation pathway.

### V2 — Functional/service endpoints

Examples include useful capacity, service availability, throughput, completed service, or delivered functionality.

**Potential use:** observable downstream consequence of a changed transformation space and subsequent execution.

**Primary risk:** these may be outcomes only. Additional justification is required before treating them as Value.

### V3 — Temporal/resource endpoints

Examples include time saved, reduced lead time, recovery time, resource consumption, or operating burden.

**Potential use:** potentially measurable consequence of transformed system capability.

**Primary risk:** improvement in an operational metric does not by itself establish that the metric represents Value for the relevant actor/system.

### V4 — Organizational/adaptive endpoints

Examples include response capability, realized flexibility, option utilization, or ability to accommodate subsequent change.

**Potential use:** potentially close to the generative/adaptive motivation of TGCV.

**Primary risk:** circularity with `T_acc` or `ΔT_acc`. A candidate must remain downstream and must not be used to construct accessibility.

### V5 — Social/welfare endpoints

Examples include access, quality of service, welfare, distributional outcomes, or other domain-defined social consequences.

**Potential use:** allows testing whether changed transformation conditions ultimately generate value in a broader stakeholder sense.

**Primary risk:** value interpretation is strongly dependent on the domain and stakeholder perspective.

## 4. Candidate audit protocol

For every empirical case, a candidate endpoint should be classified against the following questions:

1. Is the endpoint explicitly observed or reconstructible?
2. Is it downstream of the relevant transformation/trajectory?
3. Was it excluded from construction of `Pτ` and `T_acc`?
4. Is temporal ordering established?
5. Can a baseline and post-transformation state be distinguished?
6. Is the endpoint an outcome only, or is there an explicit argument that it represents Value?
7. Is the value interpretation actor/system/domain explicit?
8. Could the endpoint be affected by confounding, interference, selection, or external shocks?
9. Is reproducibility/provenance sufficient?
10. Could the endpoint support a future `ΔV` estimand without presupposing the causal result?

## 5. Existing evidence: candidate inventory to be performed

Priority cases are those with the most complete existing longitudinal chain:

1. C09 / KGFS — accessibility, transformation, outcome, and longitudinal evidence are already available; inspect existing downstream variables for independent value candidates.
2. SWIM — explicit `T_acc` reconstruction and bounded trajectory linkage; inspect performance/service/operational consequences as possible outcome or Value candidates, without relabeling them automatically.
3. IT-G1 — accessibility closure exists, but utility execution was inconclusive; inspect utility measures only as candidate endpoints and preserve the reproducibility limitation.
4. C10C001–C10C004 and MT5 — inspect documented downstream outcomes and economic/functional/social variables for candidate Value endpoints while retaining the domain-specific semantics.

No candidate is promoted merely because it is downstream or beneficial in ordinary language.

## 6. Provisional analytical classification

At this stage the five endpoint families are **candidate classes**, not TGCV Value primitives.

A candidate may receive one of the following dispositions after case-level audit:

- `V-CANDIDATE-SUPPORTED` — downstream endpoint is explicit, independent of accessibility construction, and has an explicit defensible value interpretation;
- `V-CANDIDATE-PLAUSIBLE-UNDERDEFINED` — downstream endpoint exists but value interpretation or operationalization remains incomplete;
- `OUTCOME-ONLY` — endpoint is observable downstream but no independent basis yet exists to treat it as Value;
- `REJECTED-CIRCULAR/CONTAMINATED` — endpoint enters accessibility construction or otherwise violates the independence boundary;
- `NO-CANDIDATE` — no sufficiently reconstructible downstream endpoint identified.

## 7. What this analysis does not establish

This artifact does **not** establish:

- a universal definition of TGCV Value;
- a new Core primitive;
- a universal value metric;
- `ΔT_acc → ΔV` as a causal relationship;
- a claim-level upgrade for C10, C11, C12, C13, C16 or any other claim;
- transversal validity of any endpoint family.
