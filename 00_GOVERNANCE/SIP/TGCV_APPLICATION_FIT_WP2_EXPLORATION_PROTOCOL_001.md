## 1. Purpose

This protocol operationalises the first WP2 pass agreed after the Application Fit brainstorming.

WP2 is an exploratory discovery activity. Its purpose is to identify practical problems in which TGCV may have application fit, with explicit attention to cases where transformational conditions cross disciplinary or operational boundaries.

WP2 does **not** establish scientific validity, causal validity, transversal validity, differential value, deployment readiness or TGCV Value.

## 2. Search instrument

Every candidate is screened through the following dimensions:

`mechanism class × domain/sector context × degree of transformational coupling × hibridación pattern × maturation question / next proof`

### Mechanism classes

1. opening options;
2. closing options;
3. reordering options;
4. making alternatives mutually incompatible;
5. creating capabilities;
6. removing capabilities;
7. changing transformation cost/time;
8. changing constraints determining `Pτ`.

### Coupling levels

- D0 — Single-domain
- D1 — Adjacent-domain involvement
- D2 — Cross-domain dependency
- D3 — Coupled transformation spaces
- D4 — Emergent multidomain transformation

### Hibridación patterns

1. capability propagation;
2. capability blocking;
3. cross-domain dependency;
4. cascading reconfiguration;
5. resource coupling;
6. constraint propagation;
7. trajectory coupling;
8. emergent system transformation.

## 3. Candidate screening questions

A candidate should be retained for deeper WP2 analysis only when the available description supports a concrete answer, or a clearly identifiable evidence gap, for most of the following:

1. What is the real operational problem?
2. What changes in the system/service/process?
3. What transformations are relevant before and after the change?
4. What condition determines whether a transformation is accessible/admissible?
5. Can the change plausibly modify the accessible transformation space?
6. Are subsequent consequences observable as a trajectory rather than only an immediate outcome?
7. Does another domain participate materially in that transformation or its consequences?
8. If so, is the relationship merely contextual, or does one domain alter the transformations accessible in another?
9. Which hibridación pattern best describes the relationship, if any?
10. What is the immediate question blocking maturation?
11. What is the smallest controlled next proof, study or artefact capable of answering that question?

## 4. Maturation-route classification

Each retained candidate receives a descriptive route classification, without collapsing routes into a single score.

### S — Scientific route

The immediate uncertainty concerns a scientific claim, identifiability, causal structure or reproducibility.

Next route: SIP.

### A — Applicability route

The immediate uncertainty is whether TGCV can be instantiated and used meaningfully for the concrete problem.

Next route: Applied Demonstration Cycle.

### T — Transfer/deployment route

Applicability is sufficiently specified and the main uncertainty concerns operation within a real organisational/technical environment.

Next route: Pilot / Integration Cycle.

### V — Value route

The immediate uncertainty concerns independently specified and measurable value.

Next route: Independent Value Evaluation.

Multiple routes may be relevant, but WP2 should identify the **immediate blocking question** and the smallest next proof.

## 6. Evidence discipline during exploration

Public descriptions, technical documentation, known operational cases and other sources may establish that a practical problem exists or that an opportunity hypothesis is plausible. They do not automatically establish a TGCV scientific claim.

When a candidate becomes evidence-bearing for a scientific claim, it must enter the controlled SIP circuit:

`opportunity → evidence gap → SIP → evidence generation/audit → epistemic update → RMA/Matrix/STATUS where warranted`

MOI remains the opportunity/transfer map.

## 7. Applied-demonstration discipline

If the immediate question is applicability, WP2 should preferentially identify the smallest bounded artefact that could answer it.

Possible forms include:

- mockup/wireframe;
- simulator;
- synthetic-data demonstrator;
- domain connector;
- cross-domain transformation mapper;
- small proof-of-concept;
- workflow plugin;
- digital-twin/sandbox component;
- bounded decision-support prototype.

A demonstration must eventually specify scope, inputs, TGCV representation, expected behaviour, version/reproducibility, limitations and non-claims. Prototype success is not scientific validation.

## 8. Priority search areas for the first pass

The first exploratory pass should deliberately span both conventional application domains and boundary-blurring problem classes. Candidate areas include:

- adaptive cybersecurity;
- AI agents and tool-using systems;
- cloud / edge / network orchestration and 5G;
- software evolution and DevOps;
- maintenance, manufacturing and production systems;
- supply-chain systems;
- energy and mobility/infrastructure;
- healthcare and social-service pathways;
- public-service case management;
- workforce skills and career systems.

This list is a search field, not a ranking.

## 9. First-pass output

The first WP2 pass should produce a bounded candidate register, not immediate asset revisions.

For each candidate, the output should make it possible to answer:

- why the problem is relevant;
- what transformation mechanism is involved;
- whether cross-domain coupling is substantive;
- what hibridación pattern is implicated;
- what maturation question is currently blocking progress;
- what smallest next proof should be considered.

Only after this structured exploration should WP1 revise the external assets that are actually affected.

## 10. Boundaries

This protocol does not:

- modify TGCV Core;
- modify RMA v3.35;
- modify Matrix v1.12;
- upgrade C09 or any other claim;
- establish a scientific application domain;
- establish transversal validity;
- establish differential value;
- establish product-market fit;
- authorise industrial deployment;
- replace SIP evidence controls.
