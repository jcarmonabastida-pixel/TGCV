## 2. Agreed sequence

The agreed sequence is:

**First: WP2 exploratory pass.**

**After WP2: WP1 controlled update of the affected external assets.**

WP1 is therefore not abandoned; it is deliberately sequenced after WP2 because the result of the multidomain/application-fit exploration may affect how Vision Paper, Research Prospectus, ARM and TCP frame the transfer architecture.

## 3. WP2 exploration instrument

WP2 is now explicitly instrumented around five dimensions:

`mechanism class × domain/sector context × degree of transformational coupling × hibridación pattern × maturation question / next proof`

The exploration should not merely ask whether TGCV “fits” a case. It should determine:

1. what practical problem is present;
2. what transformation mechanism is involved;
3. which domain(s) participate;
4. whether and how their transformation spaces are coupled;
5. which hibridación pattern, if any, describes that coupling;
6. whether the immediate question is scientific, applicability, deployment/transfer or value;
7. what is the smallest controlled next proof, study or artefact that can answer that question.

## 4. Minimum next proof / artefact principle

For practical opportunities, WP2 should avoid assuming that a new scientific study is always the first required step.

Where the immediate uncertainty is applicability, the preferred exploratory question may be whether a bounded artefact can instantiate the TGCV analytical workflow. Candidate artefacts include mockups, simulators, synthetic-data demonstrators, connectors, cross-domain transformation mappers, small proofs-of-concept, workflow plugins and sandbox/digital-twin components.

The artefact is to be understood as a **proof of bounded applicability/instantiability**, not as scientific validation.

Where the uncertainty is instead scientific, the appropriate route remains SIP. Where it is deployment/integration, the appropriate route is a pilot/integration cycle. Where it concerns value, the appropriate route is independent value evaluation.

## 5. Multidomain differential-value exploration

A priority question for WP2 is whether there are problems where the main difficulty is not merely that several domains coexist, but that a transformation in one domain changes the transformations accessible in another.

The strongest exploratory pattern remains:

`Domain A transformation → change in Domain B accessibility/admissibility → coupled trajectory → consequential outcome/value`

The still stronger form is a problem-of-problems in which no single domain adequately represents the compound transformation.

These remain hypotheses to investigate. WP2 must not treat the presence of a multidomain structure as evidence that TGCV has differential value.

## 6. Evidence-driven preservation

The new sequence does not weaken the evidence-driven character of the programme.

The governing architecture is:

`MOI opportunity`

with branching according to the question being asked:

`→ scientific question → SIP → scientific evidence → epistemic update`

`→ applicability question → Applied Demonstration → applicability update`

`→ deployment question → Pilot / Integration → transfer update`

`→ value question → Independent Value Evaluation → value update`

The resulting states remain distinct and must not be collapsed into a single maturity score.

## 7. Implication for WP1

Once WP2 has generated sufficient structured findings, WP1 will update the affected controlled assets using new immutable versions against the canonical scientific base.

The likely assets affected by the present line of inquiry are:

- Vision Paper;
- Research Prospectus;
- ARM;
- TCP;
- and, where required by the resulting architecture, MOI/SIP descriptions.

The updates should make the transfer architecture explicitly capable of accommodating multidomain coupling and multiple maturation routes without claiming that transversal differential value or applied-demonstration capability has already been scientifically established.
