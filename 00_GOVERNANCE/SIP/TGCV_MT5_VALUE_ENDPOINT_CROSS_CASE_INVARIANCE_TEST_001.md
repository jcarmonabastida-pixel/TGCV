# TGCV — MT5 Value Endpoint Cross-Case Invariance Test 001

**Date:** 2026-09-17  
**Status:** `CURRENT_INDEPENDENT_ANALYSIS`  
**Scope:** KGFS/C09, SWIM, IT-G1, C10C001–C10C004, MT5

## 1. Purpose

Test whether the existing candidate Value endpoints share properties that could support a domain-transversal operational criterion for `V`, without selecting a substantive endpoint family as the TGCV definition of Value.

## 2. Evidence basis

Current candidate surfaces identified in MT5 case review:

- KGFS/C09: poverty/well-being as a value-relevant downstream outcome; not yet operationalized as TGCV Value.
- IT-G1: utility measures as a plausible Value candidate; comparative utility execution remained inconclusive because independent reconstruction was incomplete.
- C10C002/MT5: downstream outcome measures with possible value interpretation; not yet operationalized as TGCV Value.
- SWIM: no sufficiently explicit downstream Value endpoint in the closed evidence.
- C10C001/C10C003/C10C004: no sufficiently complete chain supporting a TGCV Value endpoint; C10C004 is primarily reconstruction/translation evidence.

## 3. Invariance dimensions

A candidate endpoint can only be considered potentially transversal if it satisfies, independently of its substantive domain:

1. **Downstreamness:** measured after the relevant transformation/trajectory layer.
2. **Accessibility independence:** not used to define `Pτ`, `T_acc`, or `ΔT_acc`.
3. **Temporal identifiability:** baseline/post or equivalent temporal ordering is reconstructible.
4. **Construct explicitness:** the endpoint has a declared substantive meaning rather than being labelled Value solely because it improved.
5. **Stakeholder/system reference:** the entity for whom/which the endpoint represents value is explicit.
6. **Comparability:** a defensible comparison or estimand can be defined.
7. **Provenance/reproducibility:** the endpoint can be reconstructed and audited.
8. **Non-circularity:** the endpoint does not contain accessibility as a definitional component.
9. **Outcome/Value separation:** the endpoint is first established as an outcome; the additional value interpretation is separately justified.
10. **Causal neutrality:** candidate status does not presume that `ΔT_acc` caused the endpoint change.

## 4. Cross-case result

The existing cases support the **invariance of these methodological requirements**, not the invariance of a substantive Value variable.

The substantive endpoints themselves differ: socio-economic well-being, utility, and domain-specific outcomes cannot presently be reduced to one empirically established universal metric without adding an unsupported value ontology.

Therefore:

**Result: BOUNDED METHODOLOGICAL INVARIANCE — NO SUBSTANTIVE VALUE INVARIANCE ESTABLISHED.**

The strongest transversal result currently available is a criterion for what a candidate Value endpoint must satisfy, not a definition of what Value numerically or substantively is.

## 5. Candidate status

| Candidate family | Cross-case invariant property | Current disposition |
|---|---|---|
| Socio-economic/well-being | downstream, independently measurable, value interpretation possible | `PLAUSIBLE-UNDERDEFINED` |
| Utility | downstream utility construct, potentially comparable | `PLAUSIBLE-UNDERDEFINED` |
| Functional/domain outcome | downstream outcome with possible value interpretation | `PLAUSIBLE-UNDERDEFINED` |
| Operational performance alone | downstreamness only | `OUTCOME-ONLY` |
| Accessibility/capability measures | upstream/definitional relationship to `T_acc` | `REJECTED-AS-VALUE-SUBSTITUTE` |

## 6. Consequence for TGCV

The analysis does not justify a universal scalar `V`, a fixed value function, or a domain-independent weighting scheme.

It does justify a narrower candidate proposition:

> A TGCV Value endpoint, if operationalized, must be a separately defined downstream construct whose measurement is independent of accessibility construction and whose interpretation as value is explicitly justified for the relevant system/actor/domain.

This proposition is a **methodological candidate**, not yet a validated transversal rule.

## 7. Causal boundary

Nothing in this test establishes:

`ΔT_acc → ΔV`

as a causal relationship.

The test only establishes whether candidate endpoint properties recur across cases. Causal identification remains a separate C10 problem.

## 8. Disposition

**MT5-05: CLOSED — BOUNDED METHODOLOGICAL INVARIANCE; NO SUBSTANTIVE VALUE INVARIANCE.**

No Core modification.  
No claim-level upgrade.  
No definition of TGCV Value adopted.  
M9 (`ΔT_acc → ΔV`) remains open.

## 9. Next authorized analysis

The next informative operation is not another broad case inventory. It is to construct a **Value Endpoint Operationalization Gate** from the invariant methodological properties above and test whether any one existing candidate can pass it without importing an unsupported universal value ontology.
